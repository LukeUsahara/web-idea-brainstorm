# 制作用：画像圧縮ツール（TinyPNG 上位互換）

別レポジトリで実装するための計画書。  
このアイデア捻出WSから制作用WSへ渡すときは **本ファイルをそのまま貼る**。

---

## 1. プロダクト定義

### 一言

**画像をドロップするだけ。枚数・容量制限なし。全部ブラウザ内で圧縮。サーバーに送らない。**

### パクる元

[TinyPNG](https://tinypng.com/) — 月間約500万訪問。PNG/JPEG のスマート圧縮。

### 上位互換（+α）

| TinyPNG | 本作 |
|---------|------|
| 無料は **月20枚** | **枚数無制限** |
| **5MB**/ファイル上限 | 実用上は大きめも可（端末メモリが限界） |
| 画像を **サーバーにアップロード** | **ブラウザ内完結**（WASM） |
| AVIF 非対応（無料） | **任意で WebP / AVIF 出力**（v1.1） |
| 英語中心 | **日本語 UI** |
| バッチ20枚まで | **一括ドロップ・ZIP一括DL** |

### 参考（差別化の根拠）

- [ToolShare Lab 画像圧縮](https://webatives.com/) — 無制限・WASM・サーバー送信なし
- [Squoosh](https://squoosh.app/) — Google製・高品質だが1枚ずつ操作が多い

### 名前候補（未決）

- ローカル圧縮 / ピタ圧縮 / むげん圧縮 / CrushLocal など  
→ 実装開始時にドメイン・GitHub リポ名を決める

## 3. 技術スタック（推奨）

| 層 | 選定 | 理由 |
|----|------|------|
| ビルド | **Vite** | 静的サイト・Worker 分割が楽 |
| UI | **HTML + CSS + TypeScript**（React 不要でも可） | 単機能ツールは軽量が正義 |
| 圧縮 | **@jsquash/jpeg** + **@jsquash/oxipng** | Squoosh 系 WASM、実績あり |
| 変換（v1.1） | **@jsquash/webp** / **@jsquash/avif** | 同エコシステム |
| 並列処理 | **Web Worker** | MozJPEG は重い。メインスレッド禁止 |
| 一括DL | **JSZip** | クライアントのみで ZIP 生成 |
| ホスティング | **Cloudflare Pages** または **GitHub Pages** | 静的のみ。バックエンド不要 |
| 解析（任意） | Cloudflare Web Analytics | クッキーレス |

### WASM の読み込み方針

- 初回は **遅延ロード**（最初のファイルドロップ時に Worker + codec を読み込む）
- codec ごとに dynamic import（JPEG だけ使う人に AVIF を載せない）
- 目標：初回表示の JS は **&lt; 100KB**、codec は必要時のみ **+300〜500KB**

## 4. アーキテクチャ

```mermaid
flowchart LR
  User[ユーザー] --> UI[メインUI]
  UI -->|File[]| Worker[Compression Worker]
  Worker --> MozJPEG[MozJPEG]
  Worker --> OxiPNG[OxiPNG]
  Worker -->|Blob[]| UI
  UI --> Download[単体DL / ZIP]
```

### 処理フロー

1. ユーザーが画像をドロップ
2. 各ファイルの MIME を判定（jpeg / png / webp…）
3. Worker に `ArrayBuffer` を渡す（**Transferable でコピー回避**）
4. Worker が圧縮 → `Blob` を返す
5. UI が一覧に「元サイズ → 新サイズ → -XX%」を表示
6. ダウンロード or ZIP

### メモリ・上限の現実

- ブラウザのタブメモリが実質上限（**1ファイル 20〜30MB 超** は警告表示を検討）
- 同時処理は **2〜3 並列** に制限（端末負荷対策）
- TinyPNG の 5MB 制限は「サーバーコスト」の話。**本作は端末次第** と UI で説明

│  ┌ 一覧 ────────────────────────┐  │
│  │ thumb │ photo.jpg │ 2.1→0.8MB │  │

│                                     │

### 状態

- `idle` — 待機
- `loading-codec` — 初回 WASM 読込（プログレス）
- `processing` — 圧縮中（全体プログレスバー）
- `done` — 完了
- `error` — 形式非対応・メモリ不足など

## 7. 実装フェーズ

### Phase 0：セットアップ（半日）

- Vite + TypeScript プロジェクト作成
- Git 初期化・README に「サーバー送信なし」を明記
- Cloudflare Pages デプロイパイプライン

### Phase 1：MVP コア（1〜2日）

- Dropzone + ファイル読み込み
- Worker + MozJPEG で JPEG 1枚圧縮

- 前後サイズ表示 + 単体 DL

### Phase 2：バッチ + UX（1日）

- 複数ファイルキュー
- ZIP 一括 DL
- 品質スライダー

- WebP / AVIF 出力トグル
- クリップボード貼り付け

## 11. リスクと対策

| リスク | 対策 |
|--------|------|
| WASM 初回読込が重い | 遅延ロード + 「初回のみ準備中」表示 |
| 巨大画像でメモリ不足 | 50MB 超で警告、推奨 20MB 以下 |
| TinyPNG / ToolShare Lab との差別化不足 | **日本語・FAQ・AVIF** で差をつける |
| SEO で上位を取れない | 長期戦。まず「制限なし」の明示でニッチ流入 |
